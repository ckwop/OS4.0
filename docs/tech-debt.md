# Technical debt register

Known shortcuts, gaps and risks in OS 4.0, and what we plan to do about them. Add an entry when you take a shortcut or find a gap; close it, with the commit or decision that fixed it, when it is gone. Closed entries stay here as a record.

**Impact:** *high* can lose data or crash the system; *medium* wrong behaviour in some cases, or a real cost; *low* tidiness or convenience. **Must fix before public:** a blocker for any deployment reachable from the internet (milestone 11 onwards); milestone 11 cannot be done while one is open.

## Open

| ID | Debt | Impact | Plan |
| --- | --- | --- | --- |
| TD-9 | Idle costs about 5% of a core under QEMU emulation: the 100 Hz tick, the console's 10 ms key polling and the network task's 10 ms interface polling keep waking the CPU (DECISIONS.md #51, #53, #67). Polling also adds up to 10 ms to every ping. | medium on Fargate | Tickless idle (program the timer for the next wake time), and UART and virtio interrupts to wake the waiting task. Before Fargate (milestone 11). |
| TD-11 | The kernel has about 110 assembly words, against the brief's ~30. Most are constants, user variables, the bootstrap interpreter and device access; the bootstrap duplicates parsing and lookup that the Forth side also has (boot-only since TD-5). | low | Accepted by DECISIONS.md #14, #32 and #33. Revisit only if metacompilation comes back. |
| TD-13 | Stack overflow is checked at calls, branches and loops. A straight run of more than 16 pushes with none of those in between could pass the limit undetected. | low | Accepted: such code is unusual. A guard page would close it if tasks ever get their own mappings. |
| TD-14 | The repository lives under OneDrive, which syncs `build/` (a 64 MB boot image, data disks) on every build. | low (environment) | The user's call: exclude `build/` from sync, or move the repository out of OneDrive. |
| TD-17 | The network stack ignores IP options, and drops fragmented packets. | low | Reassembly only if a real need appears; nothing we send or expect is fragmented. |
| TD-18 | The address, netmask and gateway are set at boot to QEMU's user-networking values (variables `my-ip`, `netmask`, `gateway`). On EC2 the VPC assigns addresses by DHCP. | high for milestone 12 | A DHCP client over UDP, falling back to the static values. Before the EC2 AMI (milestone 12). |
| TD-21 | The dictionary is capped at 128 MiB (the reach of `bl`, DECISIONS.md #72); RAM beyond it is unused, and nothing is ever freed. That holds thousands of players, but not an unbounded number. | low | If ever needed: a page allocator over the rest of RAM for bulk data such as connection buffers, or more trampolines further into memory. |
| TD-25 | Under emulation (QEMU without KVM, as on Fargate) new password hashes get 1000-1600 PBKDF2 iterations, far below the hundreds of thousands recommended for native code. Someone who copied the data disk could guess weak passwords quickly. | medium | Run on hardware or with KVM, where calibration chooses many more iterations; rehash a password at its next login when its count is below the machine's. Revisit before milestone 11. |
| TD-26 | A client that reads one byte per retransmission timeout, or a sandbox session printing without end (`999999999 spaces`), keeps its session alive: progress resets the timeouts. Each such session holds one task and one connection, within the door's cap. | low | An output budget per input line if it is ever abused. |
| TD-27 | Every word's code field is machine code in the dictionary, beside its data. Under emulation a write to a page that holds translated code discards and retranslates it: about 40 µs per variable write in the hosted build (`qemu-aarch64`), about 0.4 µs extra on emulated bare metal. The hosted build handles a network frame in about 25 ms, and under load its network tests slow down a lot. Real hardware is unaffected. | low | Accepted (the user's call, 2026-10-27): the cost is microseconds. Indirect threading, or code fields in a separate code region, would remove it, and also TD-21's 128 MiB cap, if emulated performance ever matters. |
| TD-28 | The app disk is read only as FAT16 or FAT32 formatted whole: no partition table, no FAT12. Long-name checksums are not checked, so a long name left behind by a tool that does not know long names could be read as another file's. The hosted build opens every disk read-write, the app disk included (nothing writes it). | low | A partition table for milestone 12 if an EBS app volume needs one; the rest if it ever bites. |
| TD-29 | `telnet-key?` is true when only a telnet command (IAC ...) is waiting; the `key` that follows takes the command and then waits for a real key. A task polling `key?` while it has other work (the MUD) can stall until the next key. The CR LF case is fixed (#104). | low | Make `telnet-key?` consume complete commands too, if a client that negotiates mid-session shows it. |
| TD-30 | `make proofs` takes about 20 minutes from clean under emulation, and nearly as long after any Forth change, since every address in the generated `Words.lean` moves and Lean rebuilds the whole module. So it is a separate gate, run at each milestone, not part of `make test`. | medium | Split the generated words into a module per boot file with symbolic addresses, so a change rebuilds only what it touched; find where the per-theorem time goes (elaboration of the certificates and call obligations). Join `make test` once a typical change re-proves in under a minute (V1). |
| TD-31 | The proofs trust the model of each primitive (`proofs/OS4/Machine.lean`), the specifications that replace CATCH and THROW, the dumper and the generator's decoding of threads (a wrong decoding gives a wrong definition; a wrong certificate only fails to check). | medium | V5 proves the primitives against the assembly; a round trip (dump, regenerate, compare) tests the decoder. |
| TD-32 | The system tasks' step bounds (DECISIONS.md #108) leave out the loops that never pause, listed in `proofs/yields.txt`. Their bounds are argued there, not proven. The largest, `(tcp-output)`, sends up to 128 segments without pausing to a peer that claims a 64-byte MSS, and every SYN walks the whole connection list twice (`room?`). The proofs count only hosted drivers (`linux-net.fs`), and the counted semantics is not proven equal to the plain one. | medium | Prove each listed loop's bound from what the code above it guarantees: a frame's length, a list without a cycle, the pool's size. Or make the loop pause. Count the bare-metal driver too, and prove the two semantics agree. |
| TD-24 | The entropy HAL has a virtio-rng driver only. EC2 instances have no virtio devices, so the AMI would fall back to seeding from the clock, which an attacker can guess. | high for milestone 12 | An entropy driver for EC2 before milestone 12: the CPU's `RNDR` where the Graviton generation has it, otherwise timer jitter gathered over many samples. |

## Closed

| ID | Debt | Fixed by |
| --- | --- | --- |
| TD-1 | Nothing guarded the stacks: a task's data stack overflowed into its own user area, and its return stack into its data stack. | Stack limits checked in calls, branches, loops and `pause`; kernel errors unwind to the `catch` frame before throwing (DECISIONS.md #57). |
| TD-2 | Nothing guarded the dictionary: `allot` and `,` could write past its end. | Bounds checks throwing -8, and `unused` (#58). |
| TD-3 | The block buffer eviction path (write back a changed buffer to reuse it), `flush` and `empty-buffers` were never tested. | `tests/buffers`. |
| TD-4 | On the hosted build a bad address killed the program; bare metal recovered. | `SIGSEGV`, `SIGBUS` and `SIGILL` handlers report and throw -256 (#61). |
| TD-5 | Two lookup paths after boot: `'`, `[']` and `postpone` used the kernel's lookup, which future wordlists would not govern. | Rebuilt on the Forth `find-word` (#59). |
| TD-6 | The serial test suite ran one VM at a time, about 10 s per test. | `tools/run-tests.py` runs tests in parallel with a disk each; 18 serial tests in under a minute (#62). |
| TD-8 | Device waits (`vq-wait`) had no timeout: a device that never answered hung its task. | 5-second timeout throwing -263 (#70). |
| TD-19 | Every virtqueue had 8 entries in a fixed layout, so the NIC had 8 receive buffers. (Under QEMU this lost nothing: its network backends hold frames back while the guest has no buffers. Real NICs drop them.) | Virtqueues sized per use; 64 receive buffers (DECISIONS.md #75). `tests/udp` round-trips a burst of 48 datagrams. |
| TD-17a | No ICMP errors were sent. | Port and protocol unreachable (#74); IP options and fragments remain under TD-17. |
| TD-20 | All memory was the 1 MB dictionary inside the kernel image; the rest of RAM was unused, so pools could not grow. | The dictionary moved to RAM from the platform, up to 128 MiB (#72). Pools now `allot` from it. |
| TD-7 | The block layer is not safe for two tasks at once: a task that paused mid-request could have its buffer reused. Disk waits therefore spin without `pause` (DECISIONS.md #54). | Block words hold `blocks-lock`; device waits pause; `last-buf` and `scr` per task (DECISIONS.md #77). `tests/locks` writes 60 blocks from two tasks. |
| TD-10 | Magic numbers in more than one place: header flag bits (32, 64, 128) are written out in several Forth files, and kernel throw codes appear both as `.equ` lines and as `message:` lines. | Flag bits from the kernel as `f-` constants; the throw-code lists cross-reference each other (#79). |
| TD-12 | Assembly hot spots have no Forth reference definition beside them, although CLAUDE.md asks for one: the loop runtime (`(do)` `(loop)` `(+loop)` `i` `j`), `pick`, `um/mod`. | `pick-ref` and `um/mod-ref`, checked by `tests/reference`; the loop runtime as commented Forth (#79). |
| TD-15 | Outgoing packets share one `tx-frame`. That is safe only because building and sending a packet never pauses; a task that paused in between would have its packet overwritten. | `tx-lock` around every build-and-send (#78). |
| TD-16 | `ip` reads dotted addresses without checking them: `ip 300.1` gives a wrong address, not an error. | `ip` checks four parts of 0-255 and throws -268 (#79); `tests/ip`. |
| TD-22 | TCP hardening: predictable initial sequence numbers, resets accepted at any sequence number, no limit on connection records from a SYN flood, and a linear search for each segment's connection. Hardening also found that a half-open connection that timed out or was reset was never recycled, and that a peer MSS of 0 stalled sending. | Keyed-hash sequence numbers, RFC 5961 checks, caps on connections and half-open ones, a keyed hash table, half-open connections recycled, MSS at least 64 (DECISIONS.md #92). `tests/tcp-attack` floods, forges and checks recovery. |
| TD-23 | The network REPL had no login: anyone reaching port 4001 had full Forth. Neither port limited sessions, idle time or a client that stopped reading. | Admin password (PBKDF2, DECISIONS.md #96-97), session caps per port, an idle timeout, send and linger timeouts (#94). `tests/repl` and `tests/tcp-attack` cover them. |
